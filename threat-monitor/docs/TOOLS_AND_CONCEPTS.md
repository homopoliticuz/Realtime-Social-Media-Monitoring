# Современные инструменты, концепции и теории (п. 10)

Перечень того, что делает мониторинг эффективным и проверяемым, и как каждый элемент применён в Дозоре. Статус: **встроено** — работает в этой версии; **точка подключения** — архитектура готова, нужен ключ, модель или модуль; **рекомендация** — внедрить при развитии; **исключено** — несовместимо с политикой системы.

Сервисы и модели меняются быстро: перед внедрением проверьте актуальную доступность, лицензию и условия использования.

## 1. Правовые и этические рамки

| Концепция | Суть | В Дозоре |
|---|---|---|
| МПГПП, ст. 19–20; трёхчастный тест ограничений (законность, законная цель, необходимость и соразмерность) | Свобода выражения — правило, ограничение — исключение | Встроено: критика власти, протест, религия, политика не считаются угрозой; цель каждого поиска журналируется |
| Рабатский план действий ООН (2012) | Шесть факторов порога подстрекательства | Встроено: блок «Рабатский тест» в карточке подстрекательства |
| Стратегия и план действий ООН по борьбе с языком вражды (2019) | Реагирование на вражду без цензуры законной речи | Рекомендация для регламента реагирования |
| Christchurch Call (2019), GIFCT (Hash-Sharing Database, Incident Response Framework), Tech Against Terrorism (TCAP) | Отраслевое реагирование на террористический контент | Точка подключения: обмен хэшами медиа, протокол инцидентов |
| Регламент ЕС о цифровых услугах (DSA): ст. 16 (уведомления), ст. 22 (доверенные флаггеры), ст. 34–35 (системные риски), ст. 40 (доступ проверенных исследователей к данным) | Законные каналы доступа к данным крупных платформ и реагирования | Рекомендация: ст. 40 — разрешённый путь к данным; ст. 16/22 — каналы уведомлений |
| Регламент ЕС о террористическом контенте 2021/784 (TCO) | Удаление по распоряжению за 1 час | Справочно для работы с платформами |
| Протокол Беркли по цифровым расследованиям (OHCHR и UC Berkeley, 2022) | Сохранение, проверка и документирование онлайн-доказательств | Встроено: SHA-256 исходного текста, время, источник, происхождение, журнал с хэш-цепочкой |
| Privacy by design, оценка воздействия на защиту данных (DPIA), минимизация | Проектирование с защитой данных по умолчанию | Встроено: фрагменты вместо полных текстов, маскирование телефонов/e-mail, скрытие идентификаторов комментаторов, сроки хранения, запрет поиска по контактам |

## 2. Теории и модели оценки

| Модель | Применение | В Дозоре |
|---|---|---|
| Dangerous Speech (С. Бенеш): расчеловечивание, «обвинение в зеркальном отражении», угроза «чистоте» группы, сомнение в лояльности | Признаки речи, повышающей риск насилия против групп | Встроено: расчеловечивание и призывы к изгнанию как признаки подстрекательства |
| TRAP-18 (Дж. Р. Мелой): пути, фиксация, идентификация, новая агрессия, всплеск активности, утечка, последний довод, прямая угроза | Профессиональная оценка угроз | Встроено частично и только как признаки текста: утечка, последний довод, идентификация (героизация нападений), прямая угроза. Людей система не оценивает |
| «Путь к насилию» (Калхун и Уэстон) | Стадии от недовольства к нападению | Встроено: шкала конкретности (цель → время/место → подготовка) определяет приоритет |
| «Высказать угрозу ≠ представлять угрозу» (NTAC, Секретная служба США) | Разделение содержания и риска | Встроено: помечаются материалы, решения о людях принимают специалисты |
| ABC(DE)-модель дезинформации (К. Франсуа и др.: акторы, поведение, контент, распространение, эффект) | Анализ кампаний | Встроено частично: контент и подтверждённое распространение; анализ «акторов» намеренно не ведётся |
| DISARM | Тактики информационных операций | Рекомендация для анализа кампаний на уровне материалов |
| Структурированные аналитические методики: анализ конкурирующих гипотез (Хойер), проверка ключевых допущений | Снижение когнитивных искажений | Рекомендация для проверки критических карточек |
| Стандарты ICD 203, словарь оценочной вероятности (Ш. Кент), «Адмиралтейский» код надёжности источника и достоверности сведений | Прозрачность аналитических выводов | Встроено: факты отделены от оценок, уверенность явная; код источника — рекомендация для поля проверки |

## 3. Языковые технологии

| Инструмент | Назначение | В Дозоре |
|---|---|---|
| Многоязычный лексикон с формами (намерение, призыв, отрицание) и транслитерацией | Прозрачная базовая классификация | Встроено (17 языков, узбекская латиница и кириллица, неформальные написания `uldiraman`, транслит русского `ub'yu`) |
| Снятие обфускации («алгоспик») | Устойчивость к обходу фильтров | Встроено: омоглифы, цифры вместо букв, разделители, растянутые буквы |
| GlotLID (fastText, 1600+ языков), fastText lid.176 | Определение языка, включая uz, kk, ky, tg, tk, kaa, ug | Точка подключения: `DOZOR_GLOTLID_MODEL` |
| NLLB-200 (Meta), MADLAD-400 (Google), Argos Translate / LibreTranslate (офлайн) | Перевод запросов и материалов, в т. ч. узбекский, казахский, киргизский, таджикский, туркменский | Точка подключения: функция-переводчик в `expand_query` |
| LLM-классификатор «политика как промпт» (Claude через Anthropic API, структурированный вывод по JSON-схеме) | Второе мнение по сложным случаям, перевод неизвестных терминов | Встроено, выключено по умолчанию (`DOZOR_LLM_ENABLED=1`); цитаты-доказательства проверяются на дословность |
| Открытые модели безопасности: Llama Guard (Meta), ShieldGemma (Google), gpt-oss-safeguard (OpenAI) | Локальная классификация без передачи данных третьим лицам | Рекомендация: адаптер по образцу `analysis/llm.py` |
| Многоязычные энкодеры: XLM-RoBERTa, mDeBERTa-v3, LaBSE, multilingual-e5, BGE-M3 | Межъязыковой семантический поиск, кластеризация, дообучение классификатора | Рекомендация: поиск по смыслу через pgvector/Qdrant/OpenSearch k-NN |
| Детекторы токсичности: Detoxify (multilingual), модели TextDetox | Дополнительный сигнал | Рекомендация как вспомогательный признак (не замена контекстной оценки) |
| Морфология: Apertium (казахский, киргизский, узбекский и др.), pymorphy3, Natasha/DeepPavlov | Точная морфология вместо правил по аффиксам | Рекомендация |
| Распознавание речи: Whisper, faster-whisper, WhisperX | Транскрипты TikTok, YouTube, записей Twitch | Точка подключения: текст транскрипта анализируется как обычный материал (TikTok `voice_to_text` уже используется) |
| OCR: Tesseract (есть модели uzb, kaz, kir, tgk), PaddleOCR | Текст на мемах и скриншотах | Рекомендация |

## 4. Медиа, дубли и происхождение

| Инструмент | Назначение | В Дозоре |
|---|---|---|
| SHA-256 канонического текста, SimHash и коэффициент Жаккара | Точные дубли и похожие тексты | Встроено: дубли присоединяются к карточке как копии; сходство — техническая пометка, не связь |
| PDQ и TMK+PDQF (Meta, открытый код), хэш-базы GIFCT | Перцептивные хэши изображений и видео | Рекомендация |
| C2PA / Content Credentials | Проверка происхождения медиа | Рекомендация |
| InVID-WeVerify, обратный поиск изображений (TinEye, Google Lens, Yandex), FotoForensics/Forensically | Проверка, не является ли материал старым или подделкой | Рекомендация — только для проверки подлинности материала, не для поиска людей |
| ArchiveBox, Save Page Now (Wayback Machine), archive.today, Hunchly | Фиксация публичных страниц как доказательства | Рекомендация; в Дозоре хранится хэш исходного текста |

## 7. Сознательно исключено

Эти инструменты распространены в OSINT, но противоречат политике системы (п. 1–4, 6 ТЗ):

| Класс | Примеры | Причина |
|---|---|---|
| Перебор и связывание аккаунтов по имени пользователя | Sherlock, Maigret, WhatsMyName, social-analyzer, tookie-osint, yesitsme | Объединение сведений о человеке между платформами (п. 2) |
| Поиск по телефону и e-mail, «пробив» | Holehe, GHunt, Epieos, Telegram-боты «пробива», утёкшие базы | Установление личности по контактам (п. 2); часто незаконно |
| Распознавание лиц | PimEyes, FindClone, Search4faces | Биометрическая идентификация людей |
| Сбор списков участников групп, вступление в закрытые чаты, фейковые аккаунты | Скрейперы участников, «sock puppets» | Доступ к закрытым группам и построение сетей контактов (п. 1, 6) |
| Досье-ориентированные графы | Персональные трансформации Maltego | Персональные досье и рейтинги опасности (п. 4, 6) |
| Определение местонахождения автора | EXIF-геолокация, геолокация по фото, анализ часовых поясов | Определение местонахождения по косвенным признакам (п. 4) |

В соседних репозиториях этой учётной записи есть инструменты из первых строк таблицы. К Дозору они намеренно не подключены.
