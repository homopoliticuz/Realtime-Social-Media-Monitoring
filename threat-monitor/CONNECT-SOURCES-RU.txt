ДОЗОР — как подключить источники
================================

Где это делается
----------------
1. Запустите Start-Dozor.bat и войдите как admin (пароль в ПАРОЛИ.txt).
2. Откройте «Администрирование → Источники и ключи доступа».
3. Вставьте списки каналов и ключи, нажмите «Сохранить и применить».
   Перезапуск не нужен. Сохранённые ключи потом показываются скрытыми (•••• 1234).
4. Проверьте результат во вкладке «Источники и охват»: у источника должно быть
   состояние «подключён». Если ключ неверный, ошибка появится там и в окне поиска.

Ссылки можно вставлять как есть: t.me/канал, vk.com/club123, twitch.tv/имя,
https://mastodon.online, discord.com/channels/…/… — Дозор сам выделит нужную часть.

Без ключей работают сразу
-------------------------
• Telegram — публичные каналы: впишите @channel или https://t.me/channel
  в поле «Публичные Telegram-каналы» (по одному на строку).
  Глобального поиска по Telegram нет: ищется только по каналам из списка
  и по ссылке, вставленной в поиск.
• Mastodon — поле «Серверы Mastodon» (mastodon.social уже есть).
• RSS/Atom — поле «RSS/Atom-ленты»: адреса лент новостных сайтов и блогов.
• Любая публичная страница — просто вставьте ссылку в поле поиска.
• Bluesky — работает анонимно; для надёжности добавьте пароль приложения (ниже).

ВКонтакте
---------
1. dev.vk.com → «Создать приложение» (создаётся через кабинет VK ID;
   тип — веб-приложение или сервис).
2. В настройках приложения скопируйте «Сервисный ключ доступа».
3. Вставьте его в «Ключ доступа VK».
4. В «Публичные сообщества VK» перечислите сообщества: vk.com/club123 или
   короткие имена. Поиск идёт по стенам этих сообществ.
   Поиск по всем записям VK (newsfeed.search) работает только с ключом
   пользователя, а не с сервисным ключом.

YouTube
-------
1. console.cloud.google.com → создайте проект.
2. «API и сервисы → Библиотека» → YouTube Data API v3 → «Включить».
3. «Учётные данные → Создать учётные данные → Ключ API».
4. Вставьте ключ в «Ключ YouTube Data API v3».
   Лимит: 10 000 единиц в сутки, один поиск стоит 100 единиц (около 100 поисков).

Bluesky (по желанию)
--------------------
1. В Bluesky: Настройки → Конфиденциальность и безопасность → Пароли приложений
   → добавить пароль.
2. «Имя аккаунта Bluesky» — например, name.bsky.social;
   «Пароль приложения Bluesky» — созданный пароль (не основной пароль!).

Telegram — официальный API (по желанию, глубже публичного предпросмотра)
------------------------------------------------------------------------
1. my.telegram.org → войдите по номеру → API development tools → создайте
   приложение и скопируйте api_id и api_hash.
2. Вставьте их в группу «Telegram (официальный API)» и сохраните.
3. Дважды нажмите Telegram-Login.bat в папке Дозора: он установит нужный пакет
   и попросит войти аккаунтом аналитика (номер и код из Telegram).
   Используйте отдельный рабочий аккаунт. Читаются только публичные каналы
   из списка наблюдения; закрытые чаты и переписка не читаются.

Twitch
------
1. На twitch.tv включите двухфакторную аутентификацию (без неё приложение не создать).
2. dev.twitch.tv/console → Register Your Application: любое имя,
   OAuth Redirect URL — http://localhost, категория — Analytics Tool,
   тип клиента — Confidential.
3. Откройте приложение (Manage): скопируйте Client ID, нажмите New Secret.
4. Вставьте в группу «Twitch». Поиск идёт по названиям трансляций.
5. Чат: впишите каналы в «Каналы Twitch для захвата чата» и укажите
   «Секунд захвата чата» (например, 60). Чат читается только в реальном
   времени во время поиска — истории чата у Twitch нет.

Discord
-------
Публичного поиска по Discord нет: бот читает только серверы, куда его
добавили администраторы этих серверов.
1. discord.com/developers/applications → New Application.
2. Раздел Bot → Reset Token → скопируйте токен. Там же включите
   «Message Content Intent».
3. OAuth2 → URL Generator: отметьте bot, права View Channels и
   Read Message History. Ссылку отдайте администратору сервера.
4. ID канала: в Discord включите Настройки → Расширенные → Режим разработчика,
   затем правый клик по каналу → «Копировать ID» (или «Копировать ссылку»).
5. Токен — в «Токен бота Discord», каналы — в «ID каналов Discord».

X (Twitter)
-----------
developer.x.com → проект и приложение → Keys and tokens → Bearer Token.
Доступ к поиску платный; тарифы меняются, проверьте на сайте X.
Вставьте в «Bearer token X API».

Instagram (требуется одобрение Meta)
------------------------------------
1. Профессиональный аккаунт Instagram (бизнес или автор), связанный со
   страницей Facebook.
2. developers.facebook.com → создайте приложение, добавьте Instagram Graph API.
3. Запросите в App Review функцию «Instagram Public Content Access»
   (без неё поиск по хэштегам не работает).
4. Долгосрочный токен — в «Токен Instagram Graph API», ID бизнес-аккаунта
   Instagram — в «ID аккаунта Instagram».
   Ограничение Meta: не более 30 разных хэштегов за 7 дней.

Threads (требуется одобрение Meta)
----------------------------------
developers.facebook.com → приложение со сценарием Threads API → разрешение
threads_keyword_search (проходит проверку Meta) → токен в «Токен Threads API».
Без одобрения поиск видит только собственные публикации.

TikTok
------
Нужен одобренный доступ к TikTok Research API (developers.tiktok.com →
Research API). Его дают в основном некоммерческим исследовательским
организациям из отдельных стран — проверьте условия. После одобрения:
Client key и Client secret — в группу «TikTok Research API».

Второй классификатор (по желанию)
---------------------------------
console.anthropic.com → API Keys → ключ в «Ключ Anthropic API» и галочка
«Включить второй классификатор». Внимание: тексты материалов будут
отправляться во внешний сервис — включайте только при правовом основании.

Facebook, Одноклассники, Signal, MAX, WhatsApp
----------------------------------------------
Разрешённого интерфейса для поиска чужих публикаций у этих платформ нет
(или он выдаётся только по согласованию с платформой). Материалы, которые
вы получили законно (жалоба, обращение, выгрузка Meta Content Library),
добавляйте через «Анализ и импорт» с обязательным указанием основания.

Если источник не подключается
-----------------------------
• Смотрите текст ошибки во вкладке «Источники и охват».
• 401/403 — неверный ключ или у приложения нет нужного разрешения.
• 429 — превышен лимит платформы; уменьшите «Лимит запросов к одному источнику».
• Нет ответа ни от одного источника — проверьте интернет, прокси или брандмауэр.
